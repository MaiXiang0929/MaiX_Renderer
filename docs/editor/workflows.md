# 编辑器视口、选择与材质工作流

实现入口：[工作区](../../src/Editor/EditorWorkspace.cpp)、[视口控制](../../src/Editor/EditorViewportController.cpp)、[拾取](../../src/Editor/ViewportPicking.cpp)、[材质选择](../../src/Editor/EditorMaterialSelection.h)、[模型变换提交](../../src/Editor/EditableModelRenderer.cpp)。编辑器使用 Dear ImGui（即时模式界面库）与 ImGuizmo（变换操作工具）。

## 工作区和视口输出

`EditorWorkspace` 集中处理 Docking（窗口停靠）节点，其他面板不依赖内部停靠构建细节。默认左侧上方为视口，左下 Console（日志窗口）与 Content Browser（内容浏览窗口）共用标签；右侧 Scene（场景窗口）和 Inspector（属性窗口）并排，Material Editor（材质编辑器）与属性窗口共用最右节点。

布局通过界面配置文件保存，重置布局重新建立默认节点。首次打开材质编辑器时只迁移该窗口到属性节点；打开请求只激活一次，避免每帧抢占标签焦点。材质参数采用适合窄栏的纵向排列。

视口区域记录界面位置、逻辑大小和显示比例换算后的像素尺寸。先建立布局，再使用像素尺寸渲染，最终纹理以图像显示在视口中。OpenGL（图形接口）默认窗口帧缓冲只用于最终界面绘制。

## 模型身份和共享选择

`Application` 持有模型列表与 `EditorSelection`（编辑器选择状态），选中类型互斥表示模型、灯光、相机或空。`ModelId`（模型身份编号）在会话内稳定，名称用于显示，容器下标不作为选择身份。

模型由根变换和多个分段组成；分段保存图元、局部变换、包围球和实际材质句柄。移动模型时每个图元更新为 `根矩阵×分段局部矩阵`，无需重建网格。Scene 目前是平面列表，没有父子层级或通用实体系统。

删除模型先清理选中状态，注销分段图元、销毁网格，按实例先于父材质清理材质，然后从模型列表移除。材质面板即使关闭，应用仍同步清理失效身份。

## 拾取与坐标换算

鼠标先减视口左上角，再从逻辑尺寸换算成 GPU（图形处理器）像素坐标。CPU（中央处理器）将像素转换为 NDC（归一化设备坐标），Y 轴翻转，乘逆视图投影重建近远平面点，形成世界空间射线。

模型拾取测试每个分段的世界包围球，选择射线命中距离最近的模型。不是三角形精确拾取，细长模型或空洞区域可能出现粗命中。

灯光拾取将位置投影到屏幕，测试半径 18 像素的图标区域；命中灯光优先于模型，多个图标取较近投影深度。方向光无位置图标，不参与此路径。该优先级符合覆盖式灯光工具显示，但不读取场景深度判定真实遮挡。

## 相机与变换工具

| 操作 | 实现与用途 |
| --- | --- |
| `Alt` + 左键 | Orbit（环绕），围绕相机目标旋转 |
| `Alt` + 中键 | Pan（平移），根据视口大小换算移动 |
| `Alt` + 右键或滚轮 | Dolly（前后移动），调节相机距离 |
| `F` | 根据选中对象包围球聚焦 |
| `W/E/R` | 模型移动、旋转、缩放 |
| `Q` | 切换世界/局部操作空间 |
| `Ctrl` + 左键 | 改变主聚光灯位置方向关系 |
| `F6` | 重载着色器 |

视口图像内起始操作和焦点约束避免界面拖动误操作场景。左键释放仅在拖动距离较小且未用于环绕时产生拾取请求；变换工具使用中或鼠标在工具上时不触发普通点选。

ImGuizmo 使用视口矩形和相机矩阵。操作返回矩阵后分解平移、角度与缩放，模型缩放取正并限制在 `[0.001,1000]`；灯光工具只处理有位置灯光的平移。主灯每帧朝向场景中心，这是应用当前灯光编排策略。

## 属性与材质编辑联动

Inspector 与 Material Editor 共享 `EditorMaterialSelection`。切换模型时选择首个有效的实际使用材质；同一范围内材质失效时清空，避免列表缩短后误编辑另一个材质。相同名称不代表相同资源。

点击属性窗口材质后请求打开并激活材质标签。材质编辑器默认显示选中模型使用的去重句柄；`All materials (debug)`（全部材质调试范围）可检查其他资源。面板通过 Renderer 的只读快照显示内容，通过更新接口提交参数与纹理，不直接访问资源表内部。

`Create Instance`（创建实例）对选中模型中所有使用当前材质的分段统一替换，而非只替换列表中的单个分段。`Use Parent Material`（使用父材质）恢复父绑定；`Edit Parent`（编辑父材质）切换到父材质。纹理替换按槽位颜色空间创建，失败不提交新绑定。

## 中文资产名称显示（2026-10-11）

原问题发生在 UI 字形阶段：FBX 名称以 UTF-8 传入场景分段和材质快照，Inspector 直接提交给 ImGui；默认字体缺少中文，显示时使用问号回退。渲染材质和网格句柄不由显示名称决定。

实现入口为 [EditorFonts](../../src/Editor/EditorFonts.cpp) 与 `Application::Init()`。应用在 ImGui 后端初始化成功后、首帧之前读取 `assets/fonts/NotoSansSC.ttf`，检查已打包字体的大小和 FNV-1a 摘要，再合并基础汉字、扩展 A、中文/全角及相关标点。保留默认 13 像素英文字体，英文宽度不改变；范围数组具有静态生命周期，临时读取缓冲复制到 ImGui Atlas 自有数据后释放。缺失、读取失败、不完整或内容变化时建立默认图集，标准错误与 Console 显示回退原因。

CPU 只在初始化时构建图集，GPU 在现有 UI 绘制阶段采样图集，不修改场景光照、后处理或材质 Shader。测试图集为 2048×2048、28,309 个字形；当前 ImGui OpenGL 后端按 RGBA 上传，对应约 16 MiB GPU 纹理，字体文件约 17.8 MB。后端关闭时释放 GPU 纹理，随后 `DestroyContext()` 释放字体数据。字体范围不覆盖 BMP 之外的扩展汉字，不提供运行时字体切换。

字体来源、固定提交、SHA-256 及许可证见 [字体说明](../../assets/fonts/README.md)。现有 CMake 资产复制覆盖字体、说明和 OFL；继续沿用 `assets/` 相对路径约定，已检查从仓库根目录和可执行目录启动。

实际参考源码：[Canavar ImGuiWidget.cpp](https://github.com/berkbavas/CanavarGraphicsEngine/blob/230b44d4feb3592406f78f6aed47ea54cbdb93bd/Canavar/Engine/Source/Canavar/Engine/Util/ImGuiWidget.cpp#L76)（提交 `230b44d4feb3592406f78f6aed47ea54cbdb93bd`）只用于核对 UI 初始化边界，该文件没有中文配置；[ImGui imgui_draw.cpp](https://github.com/ocornut/imgui/blob/f5befd2d29e66809cd1110a152e375a7f1981f06/imgui_draw.cpp)（v1.91.9b，提交 `f5befd2d29e66809cd1110a152e375a7f1981f06`）用于核对范围、缺字回退、MergeMode 及数据复制所有权。本项目直接适配现有 GLFW/OpenGL 后端，不引入 Qt 或新的字体系统。

[EditorFontsTests](../../tests/Editor/EditorFontsTests.cpp) 使用 `FindGlyphNoFallback()` 检查简体、繁体及全角标点实际字形、英文字宽、中文文件路径，以及缺失、4 KiB 真字体截断和同尺寸内容损坏的回退。[FbxModelImporterTests](../../tests/Assets/Import/FbxModelImporterTests.cpp) 检查中文材质和分段名称字节完整性；临时 FBX 放在独立目录，避免纹理候选扫描受到系统 Temp 内受保护目录影响。

验证结果：Debug 构建及 17 项测试通过；默认场景分别从仓库根目录/可执行目录启动，另检查 `--material-lab` 和 `--material-instance-lab`，字体和渲染管线初始化通过，无明显初始化、Shader 编译或链接错误。用户提供的 `SK_Evernight.fbx` 实际导入为 33 材质/33 分段，材质名为 `M_Evernight_Face` 等英文名称，分段名包含 `星穹铁道—长夜月2_mesh`；264 次非 ASCII 字符出现均有实际字形，无无效 UTF-8 或字面问号。此结果验证数据与字体覆盖，不代替视觉验收。

验收步骤：从仓库根目录启动 `out/build/windows-ninja-debug/MaiX_Renderer.exe`，通过已有导入入口选择 Evernight FBX；在 Scene 选中模型，检查 Inspector 中材质及分段名称，点击材质检查 Material Editor 名称和选择同步；观察中文基线、标点、中英文混排及窄栏可读性。**显示效果与交互待用户验收。**

## 编辑器与场景叠加的边界

灯光图标和聚光锥由独立 GPU 场景叠加阶段绘制，变换工具由界面绘制。前者不受曝光/光晕影响并且不测试场景深度；后者依赖界面视口矩形。统计面板消费只读快照，展示场景数量、资源数量、提交统计与 GPU 时间。

Content Browser 当前提供已有内容相关显示与导入入口，不能据此认为已具备通用资产数据库、目录管理或资源拖放系统。没有撤销/重做、模型层级编辑或场景保存加载。

## 检查步骤

运行默认场景，调整停靠节点、打开材质标签并重启检查布局；导入两个模型，移动第二个，分别点选、聚焦、编辑与删除；检查选择联动、窄栏参数和视口拖动。

[CameraTests](../../tests/Core/CameraTests.cpp) 和 [EditorInteractionTests](../../tests/Editor/EditorInteractionTests.cpp) 覆盖相机数学、包围体、拾取与部分交互状态。真实布局、标签、输入与双模型画面仍需用户验收，自动测试不替代界面验收。

## 米制场景与相机裁剪（2026-10-02）

导入后自动聚焦一次，F 同样保存对象 ID，在下一个有效视口按实际宽高比执行。透视距离为 `1.15×世界包围球半径/sin(较小的水平或垂直半视角)`，兼容窄视口，不改变资产 Scale。Inspector 的 Position 使用米，显示源单位及根 Transform 之前的导入尺寸；默认正方体边长 2 米、Scale=1。

CPU 每帧根据模型世界包围球在主视图/反射视图的深度，以及地面四角、位置灯中心和聚光锥保守球，拟合共享相机 near/far。前后深度为 `-viewZ±radius`；near 取半个前深度并限制在 `[0.0001,0.1]` 米，far 保留 10% 加 0.01 米裕量且至少 1 米。完全在相机后的范围不参与，相交范围使用正的最小 near；位移启用时扩大局部半径再变换。此计算不分配 GPU 资源，不改变 Pass 所有权；极端尺度混合仍受传统深度缓冲精度限制。专用 Face Shadow 演示既有聚焦辅助分段排除策略保留。

默认启动场景关闭反射地面。显式材质、透明、实例测试场景保留反射地面：单一默认模型按根矩阵变换局部包围盒八角，取最低 Y 并保留间隔；多模型沿用世界包围球底部策略。场景相机独立于编辑器相机，其 authored near/far 不被自动拟合覆盖，详见 [启动场景与相机](startup-scene.md)。

验收步骤：启动默认场景，检查 Cube 的 Position/Rotation=0、Scale=1；导入 FBX，检查源单位/米制尺寸、一次性聚焦及之后的导航不被覆盖；将视口拖窄并按 F；移动、旋转、缩放正方体，检查阴影、Gizmo 和拾取；在显式测试场景检查地面及反射；小模型与大模型同场景检查近/远裁剪。结合导入警告核对异常辅助分段。数学测试通过，画面和实际交互待用户验收。
