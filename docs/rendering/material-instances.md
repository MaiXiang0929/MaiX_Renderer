# 材质实例与共享资源

实现入口：[材质资源表](../../src/Renderer/Resources/MaterialResourceStore.cpp)、[实例解析](../../src/Renderer/Resources/MaterialInstance.cpp)、[Renderer](../../src/Renderer/Core/Renderer.cpp)、[编辑请求](../../src/Core/Application.cpp)。

## 解决的问题

多个模型分段可以共享基础材质，但直接修改基础材质会影响所有引用者。Material Instance（材质实例）允许保留父材质的共同设置，仅覆盖某些参数或纹理。基础材质与实例统一使用 `MaterialHandle`，图元提交无需区分两者。

```text
父材质 + 参数覆盖掩码 + 纹理覆盖模式
    → CPU 解析
    → 稳定地址的 effective Material
    → 图元非拥有引用
    → 正常材质绑定与 GPU 着色
```

GPU（图形处理器）读取解析后的材质，不遍历继承链。CPU（中央处理器）承担父子解析与参数合法化。

## 资源身份与稳定地址

网格和材质句柄是强类型槽位编号，资源表只增加槽位，删除将槽位置空，不压缩、不复用。旧句柄解析到空槽会被拒绝，当前没有 generation（代次）字段或跨会话身份。

材质资源项由独占指针分配，容器增长不移动资源项。有效材质在同一对象内更新，因此图元缓存的 `const Material*` 地址不变。该保证依赖单线程同步修改和删除前的引用检查，不是并发安全机制。

## 参数与纹理继承

实例保存 21 组显式覆盖，包含颜色、高光兼容参数、环境反射、金属度、粗糙度、遮蔽、法线强度、透明度、卡通阈值/阴影/边缘光、面部坐标框架与轮廓设置。`FaceFrame` 将前向与右向作为同一组覆盖。

未覆盖字段复制父材质；更新某项只写该项，不把界面的整个有效快照写成其他覆盖字段。面部轴在合法化时归一化并正交化，退化方向提供回退。

每个纹理槽位有三种模式：

| 模式 | 含义 | 操作结果 |
| --- | --- | --- |
| Inherit（继承） | 使用父材质纹理 | 父替换纹理后跟随变化 |
| Replace（替换） | 使用实例自有纹理引用 | 校验纹理有效性与色彩空间 |
| Disabled（禁用） | 有意不用此纹理 | 不回退到父纹理 |

清空实例纹理表示禁用；重置槽位表示继承，两者不可混同。全部重置同时清除参数覆盖和纹理覆盖。Shading Model（着色模型）与 Blend Mode（混合模式）始终由父材质决定，实例不能覆盖队列策略。

## 更新与失败边界

更新基础材质时，`CommitBase()` 先构造父材质候选和所有直接子实例的有效候选。字符串或候选分配失败不会先改一部分对象。候选全部就绪后使用无异常移动赋值提交。

更新实例时先复制实例状态、应用改动、解析有效候选，再提交实例与有效材质。父混合模式改变后，Renderer 将新混合模式同步到父及子实例关联的所有图元，包括不可见对象。

这是一层继承：禁止以实例作为父材质，不支持嵌套、序列化、通用依赖图或 GPU 参数数组。父更新线性查找子项，适合当前对象规模。

## 分段绑定与销毁

编辑器创建实例时将其绑定到选中模型实际使用的相关分段，并更新分段保存的句柄。替换前验证全部图元的旧绑定，全部匹配后再提交，避免部分替换。`Use Parent Material`（使用父材质）恢复基础材质；`Edit Parent`（编辑父材质）明确切换编辑目标。

Renderer 拒绝销毁仍被图元引用的材质；材质表拒绝销毁仍有实例依赖的父材质。移除模型先注销图元，然后释放网格，再销毁实例和基础材质；纹理通过共享引用自然释放。重复导入模型目前建立独立资源，不执行跨模型去重。

## 验证与工作流

运行 `--material-instance-lab`，父材质与实例 A/B 三个对象共享网格。修改父粗糙度，未覆盖实例应跟随；覆盖 A 后只改变 A；禁用、替换、重置贴图应分别体现不同语义。

[MaterialInstanceTests](../../tests/Renderer/Resources/MaterialInstanceTests.cpp) 使用真实 Renderer 与 OpenGL 验证实例解析、纹理、父子依赖、销毁和分类更新，不复制生产实现。历史记录中该功能已由用户于 2026-10-01 验收；本轮文档整理没有重新执行交互验收。
