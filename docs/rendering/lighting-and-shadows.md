# 多灯光与阴影贴图

实现入口：[灯光上传](../../src/Renderer/View/LightRenderData.cpp)、[前向绘制](../../src/Renderer/Passes/ForwardPass.cpp)、[阴影阶段](../../src/Renderer/Passes/ShadowPass.cpp)、[阴影资源](../../src/Renderer/Resources/ShadowMap.cpp)、[帧投影准备](../../src/Core/Application.cpp)。

## 灯光从场景进入着色器

`LightSceneProxy`（灯光场景代理）保存世界位置、方向、类型、范围、颜色、强度与聚光锥角。每个视图分别通过 `BuildLightUploadData()` 将位置以 W=1、方向以 W=0 变换到观察空间，方向归一化，角度转余弦值，再上传 UBO（统一变量缓冲对象）。

每盏灯打包为四个四维向量，按 `std140`（标准统一缓冲内存布局）对应片段着色器的 `LightData`。最多上传 16 盏灯，超出部分按列表顺序截断并发出一次提示。没有按屏幕分块或灯光体积裁剪。

`shadowLightIndex` 是上传列表中对应阴影灯的下标；`keyLightIndex` 是卡通面部主光下标，两者分别查找。当前应用都提交主灯编号，但数据契约允许二者不同。超出上传上限的主光不会获得有效下标。

## 三类灯光的计算

| 类型 | 观察空间方向 | 衰减 |
| --- | --- | --- |
| Directional（方向光） | 灯方向的反方向 | 固定为 1 |
| Point（点光） | 表面到灯位置的归一化向量 | 根据距离与范围的平滑窗口 |
| Spot（聚光灯） | 同点光 | 距离窗口再乘内外锥余弦之间的平滑过渡 |

距离窗口为 `clamp(1-(distance/range)^4,0,1)^2`，不是物理逆平方衰减。CPU（中央处理器）限制范围和强度，GPU（图形处理器）逐像素循环灯光、计算材质响应和可见度；灯光数量增加直接扩大像素着色成本。

## 阴影两次使用几何

```text
应用计算 lightVP
    → Renderer 构建阴影视锥与可见项
    → ShadowPass 绘制深度纹理
    → 主视图/反射表面生成灯光裁剪位置
    → 片段着色器投影并比较深度
    → 可见度乘对应灯的直接光照
```

阴影图固定为 2048×2048，只有深度附件。阴影阶段只处理不透明且 `castsShadow` 为真的项；标准三角形支持实例绘制，细分路径单独读取位移贴图。地面不进入投影列表，在前向地面着色时接收阴影。

当前应用每帧根据场景包围球拟合主灯透视投影，主灯朝向场景中心，视线接近竖直时切换上方向防止观察矩阵退化。底层灯光着色支持方向光，二维阴影资源可表达方向光/聚光灯场景，但当前应用并未建立独立的方向光正交拟合策略。因此不能把“灯光类型支持方向光”写成“编辑器已完整实现方向光阴影工作流”。

## 深度比较与过滤

表面顶点输出 `lightVP×model×position`。片段阶段先除以 W，再从 NDC（归一化设备坐标）映射到纹理 `[0,1]` 范围。使用比较采样器和 3×3 PCF（百分比渐近过滤），九次深度比较取平均。

表面偏移为 `max(0.0025×(1-N·L),0.0005)`；阴影写入还启用多边形深度偏移。两者降低自阴影条纹，但过大偏移可能造成阴影脱离接触面。地面使用固定 0.001 比较偏移。

当前代码对 W 非正或超出阴影投影范围返回可见度 0。这符合现有主聚光灯“投影范围外无直射”的约定，但不是方向光通用的越界策略。关闭阴影返回 1，跳过深度比较。

## 限制与验证

只有一张二维阴影图；点光阴影、多个阴影灯、CSM（级联阴影贴图）与级联混合均未实现。透明物体不投射当前阴影，也没有 Alpha Cutout（透明度裁切）阴影。

[LightRenderDataTests](../../tests/Renderer/View/LightRenderDataTests.cpp) 验证打包、坐标变换和下标。运行默认场景，修改灯类型、位置、范围与强度，开关阴影，并切换位移路径检查初始化和着色器错误。阴影方向、接触质量与参数表现待用户验收。
